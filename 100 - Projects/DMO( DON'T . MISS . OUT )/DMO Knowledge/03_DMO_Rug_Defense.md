# DMO — Rug Defense

## Mission

Rug Defense is independent of opportunity scoring.

It asks:

> **Is there prospectively verifiable destructive control/capability against the real executable market?**

Not:

> "Does this memecoin look weird?"

## States

### PASS
Scoped checks completed; no supported catastrophic capability found.

### CAREFUL
Positive suspicious evidence exists, but proof is below VETO.

### UNKNOWN
Evidence acquisition/integrity/support failed. UNKNOWN is not the same as suspicious.

### VETO
Verified destructive mechanism/control plus meaningful current executable capability.

Only VETO is intended eventually to block.

## Current pipeline

```text
base DMO opportunity
→ holder/control evidence
→ bounded economic clustering
→ combined actor holdings
→ canonical pool capacity
→ PASS / CAREFUL / UNKNOWN / VETO
```

## Current clustering

Implemented strong relationship classes:

- verified transfer topology;
- reviewed private-funder fan-out;
- actor reuse/history.

Supporting-only evidence cannot VETO:

- fresh wallets;
- same-block timing;
- identical balances;
- synchronized behavior;
- common exchange funding.

## Disposable-wallet scammers

Assume scammers may use fresh leaf wallets for one token and discard them.

Therefore old-wallet reputation is secondary.

Primary same-token question:

> **Do apparently separate current holders form one economic actor right now?**

Prioritize:

- common upstream funder;
- verified fan-out;
- common token distributor;
- direct pre-decision transfers;
- fan-in/fan-out topology;
- objective bundle/launch linkage;
- combined cluster holdings;
- actual dump effect on canonical pool.

## Broader rug/scam coverage

Rug Defense must cover more than clustering:

1. mint/freeze/delegate/honeypot/control abuse;
2. LP/pool/migration/canonical-liquidity abuse;
3. Sybil/bundled/hidden-team economic control;
4. executable dump capability;
5. sniper/bundle/wash/fake-decentralization launch manipulation;
6. serial scam infrastructure;
7. social/project impersonation/deception;
8. post-launch deterioration/reassessment.

## Third-party graph tools

RugMaps/Bubblemaps-style tooling was investigated.

Current decision:

> **Helius/on-chain first. Third-party graph services may later be optional discovery sensors, not final authorities.**

RugMaps qualification did not verify enough useful graph/historical functionality to integrate.

## Hard limit

If wallets are independently funded, never interact, reuse no infrastructure, and coordinate only off-chain, common ownership may be impossible to prove prospectively.

DMO must not fake certainty.

## Acceptance constraints

Rug Defense must not:

- change base DMO decisions in SHADOW;
- starve provider budget;
- meaningfully delay runners;
- VETO from weak heuristics alone;
- break legitimate treasury/vesting/MM/PDA/multisig structures;
- use future outcomes in historical decisions.

Enforcement remains OFF.
